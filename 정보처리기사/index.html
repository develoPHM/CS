이상 현상 (Anomaly)

종류설명
삽입 이상데이터를 삽입할 때 원하지 않는 값(NULL 등)까지 함께 넣어야 하는 현상
삭제 이상한 튜플을 삭제할 때 필요한 다른 값까지 함께 삭제되는 현상 (연쇄 삭제)
갱신 이상중복된 데이터 중 일부만 수정되어 정보가 서로 맞지 않는 현상

함수적 종속

X의 값이 정해지면 Y의 값이 하나로 정해질 때 X → Y (X가 Y를 결정, X는 결정자·Y는 종속자)

종류설명
완전 함수적 종속Y가 기본키 X 전체에 종속
부분 함수적 종속Y가 복합 기본키의 일부에만 종속
이행적 함수적 종속X → Y이고 Y → Z일 때 X → Z가 성립

3NF2NF + 이행적 함수적 종속 제거

DROP · TRUNCATE: 삭제

제약 조건

CREATE TABLE 수강 (
  학번     INT,
  과목코드 CHAR(4),
  성적     INT DEFAULT 0 CHECK (성적 BETWEEN 0 AND 100),  -- 기본값, 값 범위 제한
  PRIMARY KEY (학번, 과목코드),                         -- 기본키 (NULL·중복 불가)
  FOREIGN KEY (학번) REFERENCES 학생(학번)               -- 외래키
    ON DELETE CASCADE                                  -- 학생이 삭제되면 수강도 삭제
    ON UPDATE CASCADE                                  -- 학번이 바뀌면 함께 변경
);

VIEW: 뷰

하나 이상의 기본 테이블에서 유도한 가상 테이블. 필요한 데이터만 보여 줘서 보안과 논리적 독립성을 높인다.

CREATE VIEW 컴공학생 AS
  SELECT 학번, 이름 FROM 학생 WHERE 학과 = '컴공'
  WITH CHECK OPTION;          -- 뷰 조건(학과='컴공')을 벗어나는 수정을 막음

DROP VIEW 컴공학생;           -- 뷰 삭제 (CASCADE, RESTRICT 사용 가능)

뷰는 ALTER로 수정할 수 없어 삭제 후 다시 만들어야 한다. 뷰를 지우면 그 뷰를 기반으로 만든 다른 뷰도 삭제되며, 삽입·삭제·갱신에 제약이 있다.

검색 속도를 높이려고 만드는 키 값과 위치(포인터)의 쌍. 조회는 빨라지지만 삽입·수정·삭제가 잦으면 관리 부담이 커진다.

DROP INDEX idx_학생이름;

SELECT 기본 구조

SELECT [DISTINCT] 컬럼, 집계함수   -- ⑤ 출력할 컬럼 (DISTINCT: 중복 제거)
FROM 테이블                      -- ① 대상 테이블
WHERE 조건                       -- ② 행 조건 (집계함수 사용 불가)
GROUP BY 컬럼                    -- ③ 그룹으로 묶기
HAVING 그룹 조건                  -- ④ 그룹 조건 (집계함수 사용)
ORDER BY 컬럼 [ASC | DESC];      -- ⑥ 정렬

GROUP BY · HAVING · ORDER BY

-- 학과별 평균 성적이 90 이상인 학과를, 평균 성적 내림차순으로
SELECT 학과, AVG(성적) AS 평균
FROM 학생
GROUP BY 학과
HAVING AVG(성적) >= 90
ORDER BY 평균 DESC;

-- a는 오름차순, a가 같으면 b는 내림차순
SELECT * FROM T ORDER BY a ASC, b DESC;

WHERE vs HAVING "○○별" 문제는 GROUP BY. 집계 함수(SUM, AVG, MAX 등)에 조건을 걸 때는 WHERE가 아니라 HAVING을 쓴다. ORDER BY의 기본값은 ASC(오름차순)다.

트리거와 프로시저

트리거 (Trigger)

테이블에 삽입·갱신·삭제 같은 이벤트가 발생하면 자동으로 실행되는 SQL 블록. 무결성 유지, 로그 기록 등에 쓴다.

CREATE TRIGGER 학생등록로그
AFTER INSERT ON 학생            -- BEFORE / AFTER, INSERT / UPDATE / DELETE
FOR EACH ROW                   -- 행마다 실행
BEGIN
  INSERT INTO 로그 VALUES (:NEW.학번, SYSDATE);   -- NEW: 새 값, OLD: 이전 값
END;

주의 트리거 안에서는 COMMIT, ROLLBACK 같은 트랜잭션 제어 명령을 사용할 수 없다.

프로시저 (Stored Procedure)

자주 쓰는 여러 SQL 문을 하나로 묶어 DB에 저장해 두고, 필요할 때 호출해서 실행하는 프로그램

CREATE PROCEDURE 급여인상 (p_사번 IN INT)
IS
BEGIN
  UPDATE 사원 SET 급여 = 급여 * 1.1 WHERE 사번 = p_사번;
END;

EXECUTE 급여인상(100);          -- 호출 (EXEC, CALL도 사용)

값을 돌려주는(RETURN) 것은 사용자 정의 함수, 이벤트에 자동으로 반응하는 것은 트리거, 직접 호출해서 실행하는 것은 프로시저다.

기법설명
OPTOPTimal, 최적 교체앞으로 가장 오랫동안 사용하지 않을 페이지를 교체. 벨레이디(Belady)가 제안했고 페이지 부재가 가장 적지만, 미래 참조를 알 수 없어 실제 구현은 불가능 (비교 기준용)
FIFOFirst In First Out가장 먼저 들어온 페이지를 교체. 적재 시간을 기억해 두고 가장 오래 있던 페이지를 내보냄. 이해·구현이 간단. 프레임을 늘려도 부재가 늘 수 있음(벨레이디의 모순)
LRULeast Recently Used최근에 가장 오랫동안 사용하지 않은 페이지를 교체. 페이지마다 계수기(Counter)나 스택(Stack)을 두어 가장 오래전에 사용된 페이지를 찾음
LFULeast Frequently Used사용 횟수가 가장 적은 페이지를 교체. 자주 쓰는 페이지는 횟수가 많아 남음
SCRSecond Chance, 2차 기회FIFO의 단점을 보완. 오래 있던 페이지라도 참조 비트가 1이면 비트를 0으로 바꾸고 한 번 더 기회를 줌. 자주 쓰는 페이지가 교체되는 것을 막음
NURNot Used RecentlyLRU와 비슷하게 최근에 사용하지 않은 페이지를 교체. LRU의 시간 오버헤드를 줄이려고 페이지마다 참조 비트와 변형 비트(Modified, Dirty Bit) 두 개를 사용

ls -l의 권한 표시 -rwxr-xr--는 파일 종류(1자리) + 소유자 · 그룹 · 기타 사용자(3자리씩)로 읽는다.

권한의미숫자
r읽기 (Read)4
w쓰기 (Write)2
x실행 (eXecute)1
-권한 없음0
 
chmod 754 a.txt    # 소유자 rwx(4+2+1=7), 그룹 r-x(4+1=5), 기타 r--(4) → -rwxr-xr--
chmod 644 a.txt    # rw-r--r-- (일반 파일의 흔한 권한)
chmod u+x a.txt    # 소유자(u)에게 실행 권한 추가 (g: 그룹, o: 기타, a: 모두)
chmod go-w a.txt   # 그룹과 기타 사용자의 쓰기 권한 제거
chown user1 a.txt  # 파일 소유자 변경

예시 문제

소유자는 읽기·쓰기·실행, 그룹은 읽기·실행, 기타 사용자는 읽기만 가능하도록 a.txt의 권한을 설정하는 명령어를 8진수로 쓰시오.

풀이

소유자 rwx = 4+2+1 = 7, 그룹 r-x = 4+0+1 = 5, 기타 r-- = 4 → chmod 754 a.txt

NAT (Network Address Translation)

사설 IP를 공인 IP로(또는 반대로) 변환하는 기술. 부족한 공인 IP를 아끼고 내부망 구조를 외부에 숨긴다.

종류설명
정적 NATStatic사설 IP 하나를 공인 IP 하나에 1:1 고정으로 연결
동적 NATDynamic공인 IP 풀에서 사용할 때마다 동적으로 할당
PAT (NAPT)Port Address Translation포트 번호까지 이용해 공인 IP 하나를 여러 사설 IP가 함께 사용

네트워크: 전송 오류 제어

전송 오류 발생 원인

원인설명
지연 왜곡주파수에 따라 신호의 전달 속도가 달라 생기는 왜곡
상호 변조(간섭) 잡음서로 다른 주파수가 같은 전송 매체를 공유할 때 생기는 간섭
충격성 잡음순간적으로 크게 발생하는 잡음. 데이터 전송 오류의 주된 원인
시스템적 왜곡전송 시스템의 특성 때문에 일정하게 발생하는 왜곡 (감쇠 등)

전송 오류 제어 방식

방식설명
FEC전진 오류 수정, Forward Error Correction재전송 요구 없이 수신 측이 스스로 오류를 검출하고 수정
  • 오류가 나도 송신 측에 통보하지 않음
  • 오류 정정용 제어 비트가 추가되어 전송 효율이 떨어짐
  • 해밍 코드, 상승 코드
BEC후진 오류 수정, Backward Error Correction오류가 나면 송신 측에 재전송을 요구
  • 오류 검출: 패리티 검사, CRC, 블록 합 검사
  • 오류 제어: 자동 반복 요청(ARQ)

ARQ (자동 반복 요청)

수신 측이 오류 발생을 송신 측에 통보하면, 송신 측이 오류가 난 블록을 재전송한다.

종류설명
Stop-and-Wait ARQ정지-대기블록 1개를 보낸 뒤 수신 측의 응답을 기다림. 구현은 단순하지만 전송 효율이 떨어짐
Continuous ARQ연속Stop-and-Wait의 오버헤드를 줄이려고 데이터 블록을 연속으로 보냄
  • Go-Back-N: 오류가 난 블록부터 이후 블록을 모두 재전송
  • Selective Repeat: 오류가 난 블록만 골라 재전송

오류 검출·정정 방식

방식설명
Parity Check패리티 검사전송 비트에 패리티 비트 1비트를 추가해 오류 발생 유무만 판별
  • 홀수 패리티: 1의 개수가 홀수가 되도록 맞춤
  • 짝수 패리티: 1의 개수가 짝수가 되도록 맞춤
CRC순환 중복 검사다항식 코드로 오류 발생 유무를 판별. 집단 오류도 검출하고 검출률이 높아 HDLC 프레임의 FCS에 사용
Block Sum Check블록 합 검사블록의 맨 끝에 수평 방향 패리티 비트를 붙여 오류 발생 유무를 판별. 수평 패리티 검사, 세로 중복 검사(LRC)라고도 함
Hamming Code해밍 코드수신 측이 직접 오류를 검출하고 수정까지 하는 자기 정정 부호. 1비트 오류만 수정 가능

해밍 거리 송·수신 데이터에서 서로 대응하는 비트 중 값이 다른 비트의 개수

네트워크: 패킷 교환 방식

구분가상 회선 (Virtual Circuit)데이터그램 (Datagram)
연결연결형. 전송 전에 논리적 연결(가상 회선)을 먼저 설정비연결형. 연결 설정 없이 바로 전송
경로모든 패킷이 설정된 같은 경로로 이동패킷마다 경로를 동적으로 결정해 서로 다른 경로로 갈 수 있음
순서보낸 순서대로 도착도착 순서가 바뀔 수 있어 목적지에서 재정렬 필요
장단점순서 보장, 안정적. 연결 설정 시간이 필요하고 경로에 장애가 나면 영향이 큼설정 시간이 없고 장애 경로를 피해 갈 수 있어 유연. 순서와 전달이 보장되지 않음
예시X.25, 프레임 릴레이, ATM인터넷의 IP. 웹 페이지 요청 시 패킷들이 여러 경로로 독립적으로 전달

주의 전화 통화는 가상 회선이 아니라, 실제 물리 회로를 통화 동안 점유하는 회선 교환 방식이다.

네트워크: 라우팅 프로토콜

데이터를 목적지까지 효율적으로 전달하기 위한 경로 결정 규칙

정적 라우팅
관리자가 경로를 수동으로 설정. 구성이 바뀌면 직접 갱신해야 함. 소규모 네트워크나 특정 경로를 강제할 때 적합하고 자원을 아낌
동적 라우팅
라우터끼리 경로 정보를 자동으로 교환해 최적 경로를 선택. 네트워크 변화에 유연하게 대처. 자치 시스템(AS) 범위에 따라 IGP와 EGP로 나뉨
프로토콜설명
IGPInterior Gateway Protocol같은 AS 내부에서 라우터 간 경로를 교환
RIPIGP · 거리 벡터홉 수를 기준으로 최단 경로를 찾음. 벨만-포드 알고리즘. 최대 15홉까지만 가능해 소규모 네트워크에 적합. 30초마다 라우팅 정보 갱신
OSPFIGP · 링크 상태링크 상태 정보로 최적 경로를 계산. 다익스트라 알고리즘. 홉 수 제한이 없어 중·대규모 네트워크에 적합. 영역(Area)으로 나눠 관리
EIGRPIGP · 고급 거리 벡터Cisco가 개발. 대역폭, 지연, 신뢰도 등 여러 요소를 고려해 경로를 설정. 대규모 네트워크에 적합
EGPExterior Gateway Protocol서로 다른 AS 사이에서 경로를 교환
BGPEGP · 경로 벡터인터넷의 AS 간 라우팅에 쓰는 대표 프로토콜. TCP(179번 포트) 위에서 동작해 신뢰성이 높음. 경로 길이, 라우팅 정책 등을 고려해 경로를 선택

짝 외우기 RIP = 거리 벡터 = 벨만-포드 = 홉 수 · OSPF = 링크 상태 = 다익스트라
