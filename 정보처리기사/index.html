함수적 종속

X의 값이 정해지면 Y의 값이 하나로 정해질 때 X → Y (X가 Y를 결정, X는 결정자·Y는 종속자)

제약 조건에 이름 붙이기: CONSTRAINT

2026년 1회 출제 이름이 있는 외래키 제약 조건을 CREATE TABLE 안에 작성하기 (빈칸: CONSTRAINT, FOREIGN, 컬럼, REFERENCES, 참조 컬럼)

CREATE TABLE 선수 (
  선수ID  CHAR(7)     NOT NULL,
  팀ID    CHAR(3)     NOT NULL,
  CONSTRAINT pk_선수 PRIMARY KEY (선수ID),
  CONSTRAINT fk_선수팀 FOREIGN KEY (팀ID) REFERENCES 팀 (팀코드)
);
-- 형식: CONSTRAINT 제약조건명 FOREIGN KEY (외래키 컬럼) REFERENCES 참조테이블 (참조 컬럼)

ALTER TABLE 선수 ADD CONSTRAINT fk_선수팀 FOREIGN KEY (팀ID) REFERENCES 팀 (팀코드);   -- 나중에 추가
ALTER TABLE 선수 DROP CONSTRAINT fk_선수팀;                                             -- 삭제

제약 조건에 이름을 붙여 두면 나중에 그 이름으로 삭제하거나 수정할 수 있다. 외래키 컬럼 이름과 참조하는 컬럼 이름은 달라도 된다.

VIEW: 뷰

하나 이상의 기본 테이블에서 유도한 가상 테이블. 필요한 데이터만 보여 줘서 보안과 논리적 독립성을 높인다.

CREATE VIEW 컴공학생 AS
  SELECT 학번, 이름 FROM 학생 WHERE 학과 = '컴공'
  WITH CHECK OPTION;          -- 뷰 조건(학과='컴공')을 벗어나는 수정을 막음

DROP VIEW 컴공학생;           -- 뷰 삭제 (CASCADE, RESTRICT 사용 가능)

뷰는 ALTER로 수정할 수 없어 삭제 후 다시 만들어야 한다. 뷰를 지우면 그 뷰를 기반으로 만든 다른 뷰도 삭제되며, 삽입·삭제·갱신에 제약이 있다.

DISTINCT COUNT(열)과 COUNT(DISTINCT 열) 부서가 A, A, B, B, B인 5행일 때 SELECT DISTINCT COUNT(부서)는 먼저 COUNT(부서) = 5를 구한 뒤 그 한 행에서 중복을 없애므로 5, SELECT COUNT(DISTINCT 부서)는 서로 다른 부서 수 2다 (2022년 3회 출제). DISTINCT가 괄호 안에 있어야 중복 제거 후 센다.

GROUP BY · HAVING · ORDER BY

-- 학과별 평균 성적이 90 이상인 학과를, 평균 성적 내림차순으로
SELECT 학과, AVG(성적) AS 평균
FROM 학생
GROUP BY 학과
HAVING AVG(성적) >= 90
ORDER BY 평균 DESC;

-- a는 오름차순, a가 같으면 b는 내림차순
SELECT * FROM T ORDER BY a ASC, b DESC;

WHERE vs HAVING "○○별" 문제는 GROUP BY. 집계 함수(SUM, AVG, MAX 등)에 조건을 걸 때는 WHERE가 아니라 HAVING을 쓴다. ORDER BY의 기본값은 ASC(오름차순)다.

-- 과목별 평균이 90 이상인 과목의 이름, 최소 점수, 최대 점수 (WHERE 없이)
SELECT 과목 AS 과목이름, MIN(점수) AS 최소점수, MAX(점수) AS 최대점수
FROM 성적
GROUP BY 과목
HAVING AVG(점수) >= 90;

별칭(AS)은 결과의 열 이름을 바꾼다. AS는 생략할 수 있고, 별칭에 공백이 있으면 따옴표로 감싼다. 조건에 쓰는 집계 함수(AVG)가 SELECT에 없어도 HAVING에는 쓸 수 있다 (2023년 1회 출제).

FROM emp e JOIN proj p ON e.pid = p.pid
WHERE p.pid IN (

);

트리거 (Trigger)

테이블에 삽입·갱신·삭제 같은 이벤트가 발생하면 자동으로 실행되는 SQL 블록. 무결성 유지, 로그 기록 등에 쓴다.

CREATE TRIGGER 학생등록로그
AFTER INSERT ON 학생            -- BEFORE / AFTER, INSERT / UPDATE / DELETE
FOR EACH ROW                   -- 행마다 실행
BEGIN
  INSERT INTO 로그 VALUES (:NEW.학번, SYSDATE);   -- NEW: 새 값, OLD: 이전 값
END;

주의 트리거 안에서는 COMMIT, ROLLBACK 같은 트랜잭션 제어 명령을 사용할 수 없다.

프로시저 (Stored Procedure)

자주 쓰는 여러 SQL 문을 하나로 묶어 DB에 저장해 두고, 필요할 때 호출해서 실행하는 프로그램

CREATE PROCEDURE 급여인상 (p_사번 IN INT)
IS
BEGIN
  UPDATE 사원 SET 급여 = 급여 * 1.1 WHERE 사번 = p_사번;
END;

EXECUTE 급여인상(100);          -- 호출 (EXEC, CALL도 사용)

값을 돌려주는(RETURN) 것은 사용자 정의 함수, 이벤트에 자동으로 반응하는 것은 트리거, 직접 호출해서 실행하는 것은 프로시저다.

솔트와 키 스트레칭 솔트(Salt): 해시하기 전에 비밀번호에 무작위 값을 덧붙여, 같은 비밀번호라도 해시 값이 달라지게 함 → 레인보우 테이블 공격 방어 · 키 스트레칭(Key Stretching): 해시를 여러 번 반복해 무차별 대입에 드는 시간을 늘림. 예: bcrypt, PBKDF2, scrypt

PEM (Privacy Enhanced Mail)

IETF가 만든 인터넷 이메일 보안 표준(암호화, 인증, 무결성)이다. 지금은 개인키·공개키·인증서를 Base64 텍스트로 저장하는 파일 형식(.pem)으로 더 많이 쓰이며, SSL/TLS 인증서 설정에 흔히 사용한다.

상속, 생성자, 오버라이딩

2026년 2회 출제 자식 생성자의 super() 호출, 오버라이딩한 메서드 안의 super.메서드() 호출, 접근 제어자와 출력 연산

class Parent {
    int x;
    Parent(int x) { this.x = x; System.out.print("P"); }
    void show() { System.out.print(x); }
}
class Child extends Parent {
    Child(int x) { super(x * 2); System.out.print("C"); }   // 부모 생성자 먼저
    @Override
    void show() { super.show(); System.out.print("!"); }     // 부모 메서드 호출 후 추가 출력
}
// main
Parent p = new Child(3);   // 출력: PC   (부모 생성자 → 자식 생성자)
p.show();                  // 출력: 6!   (실제 객체가 Child라서 Child의 show 실행)
// 최종 출력: PC6!
개념핵심
생성자 순서자식 객체를 만들면 부모 생성자가 먼저 실행된다. super(값)은 자식 생성자의 첫 줄에서 부모 생성자를 호출
오버라이딩부모 메서드를 자식이 같은 이름·매개변수로 재정의. super.메서드()로 부모 버전을 호출할 수 있음
부모 메서드 안의 호출super.draw()로 부모 메서드에 들어갔어도, 그 안에서 다시 부르는 draw()(= this.draw())는 실제 객체(자식)의 것이 실행됨 (2023년 3회 출제)
동적 바인딩Parent p = new Child()처럼 부모 타입 변수라도, 오버라이딩된 메서드는 실제 객체(Child)의 것이 실행됨
private 필드자식에게 상속은 되지만 자식 코드에서 직접 접근할 수 없음. 부모의 메서드(생성자, set 등)를 통해서만 값을 넣고 읽음

오버로딩과 오버라이딩이 함께 있을 때

2026년 1회 출제 부모 타입 변수로 호출한 메서드 안에서, 자식이 오버로딩과 오버라이딩을 모두 한 메서드를 부르는 문제

class P {
    void m(Object o) { System.out.print("P-obj "); }
}
class K extends P {
    void m(Object o) { System.out.print("K-obj "); }   // 오버라이딩 (P의 m(Object) 재정의)
    void m(String s) { System.out.print("K-str "); }   // 오버로딩 (K에만 있는 새 메서드)
}
// main
P p = new K();
p.m("hi");      // K-obj   ① 컴파일 때 P에는 m(Object)뿐 → m(Object) 선택
                //         ② 실행 때 실제 객체 K의 m(Object) 실행
K k = new K();
k.m("hi");      // K-str   K 타입에는 m(String)이 있어 더 구체적인 쪽 선택

어떤 시그니처를 부를지(오버로딩 선택)는 컴파일할 때 변수의 타입으로 정해지고, 누구의 메서드를 실행할지(오버라이딩)는 실행할 때 실제 객체로 정해진다. 부모 클래스의 메서드 안에서 호출하는 경우도 부모 타입 기준으로 시그니처가 정해진다.

출력문의 + 연산

System.out.print(1 + 2 + "a" + 1 + 2);   // 3a12  (왼쪽부터: 1+2=3 → "3a" → "3a1" → "3a12")
System.out.print(9 + 500);               // 509   (둘 다 숫자면 덧셈)
System.out.print("" + 9 + 500);          // 9500  (문자열이 앞에 오면 이어 붙임)

+는 왼쪽부터 계산한다. 숫자끼리는 덧셈이고, 한쪽이라도 문자열이 되는 순간부터는 문자열 연결이다.

인터페이스와 추상 클래스

2025년 3회 출제 인터페이스를 구현하는 클래스 선언의 키워드 (빈칸: implements)

interface Shape {
    double area();                       // 자동으로 public abstract
}
abstract class Base {
    abstract void draw();                // 몸체 없는 추상 메서드
    void hello() { System.out.print("hi"); }   // 일반 메서드도 가질 수 있음
}
class Circle extends Base implements Shape {   // 클래스 상속은 extends, 인터페이스 구현은 implements
    public double area() { return 3.14; }       // 인터페이스 메서드는 public으로 구현
    void draw() { System.out.print("O"); }
}
구분키워드개수
클래스 → 클래스extends하나만
클래스 → 인터페이스implements여러 개 가능 (implements A, B)
인터페이스 → 인터페이스extends여러 개 가능

인터페이스와 추상 클래스는 new로 직접 객체를 만들 수 없고, 구현(상속)한 클래스가 추상 메서드를 모두 구현해야 객체를 만들 수 있다.

참조 전달: 배열과 객체

2025년 2회 출제 메서드에 배열과 문자열을 넘긴 뒤 값이 바뀌는지, 배열 안의 객체 참조를 서로 바꾼 뒤 필드를 수정하는 문제

static void change(int[] arr, int n, String s) {
    arr[0] = 100;     // 배열 참조를 통해 원본 배열의 칸을 수정 → 원본에 반영
    n = 100;          // 기본형은 값이 복사됨 → 원본 그대로
    s = "Z";          // 매개변수에 새 객체를 대입해도 원본 변수는 그대로
}
int[] arr = {1}; int n = 1; String s = "A";
change(arr, n, s);
System.out.print(arr[0] + " " + n + " " + s);   // 100 1 A

class Box { int v; Box(int v) { this.v = v; } }
Box a = new Box(1), b = new Box(2);
Box[] boxes = {a, b};
boxes[0] = boxes[1];     // 배열 칸이 b를 가리키도록 바뀔 뿐, 변수 a는 그대로 Box(1)
boxes[0].v = 9;          // boxes[0]은 b와 같은 객체 → b.v = 9
System.out.print(a.v + " " + b.v);              // 1 9

Java는 항상 값을 복사해서 넘긴다. 다만 배열·객체 변수에 들어 있는 값은 주소(참조)라서, 그 주소로 내용을 바꾸면 원본이 바뀌고, 변수에 다른 객체를 대입하면 원본과 끊어진다. 객체를 여러 변수가 함께 가리키고 있으면 화살표를 그려서 추적한다.

static 메서드와 필드는 오버라이딩되지 않음

2025년 2회 출제 부모 타입 변수로 자식 객체의 인스턴스 메서드와 static 메서드를 각각 호출

class P {
    int x = 1;
    static String id() { return "P"; }
    String name() { return "p"; }
}
class C extends P {
    int x = 2;
    static String id() { return "C"; }   // 오버라이딩이 아니라 '숨김'(hiding)
    String name() { return "c"; }        // 오버라이딩
}
P r = new C();
r.name();     // "c"  인스턴스 메서드: 실제 객체(C) 기준
r.id();       // "P"  static 메서드: 변수 타입(P) 기준
r.x;          // 1    필드: 변수 타입(P) 기준
((C) r).x;    // 2    C 타입으로 형변환하면 C의 필드

실제 객체를 따라가는 것은 인스턴스 메서드(오버라이딩)뿐이다. static 메서드와 필드는 변수의 선언 타입을 따른다.

람다식과 예외 처리

2025년 2회 출제 함수형 인터페이스를 람다로 구현하고, 예외를 던지면 catch에서 다른 값을 반환하는 문제

interface Op { int apply(int x) throws Exception; }   // 추상 메서드가 하나인 함수형 인터페이스

static int run(Op op) {
    try {
        return op.apply(5);
    } catch (Exception e) {
        return -1;                     // 예외가 나면 여기로
    } finally {
        System.out.print("F");         // 예외 여부와 상관없이 항상 실행 (return 직전에)
    }
}
Op a = x -> { if (x > 3) throw new Exception(); return x * 2; };
Op b = x -> x + 1;                     // 한 줄이면 중괄호와 return 생략 가능

System.out.print(run(a) + run(b));
// run(a): 5 > 3 → 예외 → catch에서 -1, finally가 F 출력
// run(b): 6 반환, finally가 F 출력
// 마지막에 -1 + 6 = 5 출력 → 전체 출력: FF5

람다식 (매개변수) -> { 본문 }은 인터페이스의 추상 메서드 하나를 바로 구현한 것이다. try에서 예외가 발생하면 나머지 코드는 건너뛰고 catch로 가며, finally는 return이 있어도 반드시 실행된다.

여러 개의 catch와 예외 종류

2025년 1회 출제 0으로 나눴을 때 여러 catch 중 어느 블록이 실행되는지, finally 출력 순서

try {
    int[] a = new int[2];
    a[3] = 1;                                   // 여기서 예외 발생 → 아래 줄은 실행 안 됨
    System.out.print("A");
} catch (ArithmeticException e) {
    System.out.print("B");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.print("C");                      // 위에서부터 처음 맞는 catch 하나만 실행
} catch (Exception e) {
    System.out.print("D");                      // 이미 처리됐으므로 실행 안 됨
} finally {
    System.out.print("E");
}
// 출력: CE
예외발생 상황
ArithmeticException정수를 0으로 나눔 (실수 5.0 / 0은 예외 없이 Infinity)
ArrayIndexOutOfBoundsException배열 범위를 벗어난 인덱스 사용
NullPointerExceptionnull인 참조로 메서드나 필드에 접근
NumberFormatException숫자가 아닌 문자열을 숫자로 변환 (Integer.parseInt("abc"))
ClassCastException변환할 수 없는 타입으로 형변환

catch는 위에서부터 차례로 비교해 처음 맞는 하나만 실행한다. 모든 예외의 부모인 Exception은 맨 아래에 둬야 한다 (위에 두면 아래 catch에 닿을 수 없어 컴파일 오류).

객체 생성 순서와 부모 생성자 안의 메서드 호출

2025년 1회 출제 부모 생성자 안에서 호출한 메서드가 자식에서 오버라이딩되어 있을 때, static 변수에 값이 쌓이는 순서

class A {
    static int log = 0;
    A() { log += 1; show(); }        // ② 부모 생성자: show()는 자식 것이 실행됨
    void show() { log += 10; }
}
class B extends A {
    int n = 5;                       // ③ 자식 필드 초기화 (부모 생성자가 끝난 뒤)
    B() { log += n; show(); }        // ④ 자식 생성자 본문
    @Override
    void show() { log += 100; }
}
new B();                             // ① B() 호출 → 첫 줄에 숨어 있는 super() 로 A() 먼저
System.out.print(A.log);
// A(): 1 → B.show(): 101 → n = 5 → B(): 106 → B.show(): 206   출력: 206

class P {

    P(int x) { this.x = x; }       // P의 x = 7
    int getX() { return x; }       // P 안의 코드 → P의 x
}
class C extends P {
    int x = 2;                     // P의 x와 별개인 C의 x (필드 숨김)

}

obj.getX();    // 7    getX()는 P에 정의되어 있어 P의 x를 읽음
obj.x;         // 9    변수 타입이 C → C의 x

ctype.h 문자 판별과 문자 이동

2024년 1회 출제 대문자·소문자·숫자를 판별해 각각 일정 칸 밀어서 바꾸는 암호화 코드 (대문자에 % 25를 쓴 함정 포함)

const char *s = "Ab 9z";

    if (isupper(s[i]))      r[i] = (s[i] - 'A' + 1) % 26 + 'A';   // 대문자 한 칸 이동
    else if (islower(s[i])) r[i] = (s[i] - 'a' + 1) % 26 + 'a';   // 소문자 한 칸 이동 (z → a)
    else if (isdigit(s[i])) r[i] = (s[i] - '0' + 1) % 10 + '0';   // 숫자 한 칸 이동 (9 → 0)
    else                    r[i] = s[i];                          // 공백 등은 그대로
}
r[i] = '\0';
printf("%s", r);    // Bc 0a

isupper(대문자), islower(소문자), isdigit(숫자), isalpha(알파벳)는 참이면 0이 아닌 값을 돌려준다. (c - 'A' + k) % 26 + 'A'는 "알파벳 순번 → k칸 이동 → 다시 문자"다. 나누는 수가 26이 아니면(예: 25) 결과가 달라지므로 숫자를 그대로 계산한다.

2차원 동적 배열과 인덱스 변환

int R = 2, C = 3;
int **a = malloc(sizeof(int*) * R);       // 행 포인터 R개
for (int i = 0; i < R; i++)
    a[i] = malloc(sizeof(int) * C);       // 각 행에 int C개

for (int k = 0; k < R * C; k++)
    a[k / C][k % C] = k;                  // 1차원 번호 k → 행 k / C, 열 k % C
// a = { {0, 1, 2},
//       {3, 4, 5} }   → a[1][0] = 3, a[1][2] = 5

for (int i = 0; i < R; i++) free(a[i]);   // 행부터 해제한 뒤
free(a);                                  // 행 포인터 배열 해제

1차원 번호 k를 2차원으로 바꿀 때 행 = k / 열 개수, 열 = k % 열 개수. 문제에서 식이 복잡하면 k = 0, 1, 2…마다 행·열을 표로 적어 채운다.

원형 큐와 스택

2025년 2회 출제 배열과 % SIZE로 구현한 원형 큐에 삽입·삭제를 반복한 뒤 꺼낸 값

#define SIZE 3
typedef struct { int a[SIZE]; int front, rear; } Queue;

void enq(Queue *q, int v) { q->a[q->rear] = v;  q->rear  = (q->rear + 1) % SIZE; }
int  deq(Queue *q) { int v = q->a[q->front]; q->front = (q->front + 1) % SIZE; return v; }

Queue q = {{0}, 0, 0};
enq(&q, 10); enq(&q, 20);   // a = [10, 20, _]   rear = 2
deq(&q);                    // 10 꺼냄           front = 1
enq(&q, 30);                // a = [10, 20, 30]  rear = 0 (끝에서 처음으로 돌아감)
enq(&q, 40);                // a = [40, 20, 30]  rear = 1 (꺼낸 자리를 재사용)
deq(&q); deq(&q); deq(&q);  // 20, 30, 40 순서로 꺼냄
자료구조방식연산
큐 (Queue)FIFO: 먼저 넣은 것이 먼저 나옴rear로 삽입(enqueue), front로 삭제(dequeue)
원형 큐배열 끝에 닿으면 % SIZE로 처음으로 돌아가 빈자리를 재사용(인덱스 + 1) % SIZE
스택 (Stack)LIFO: 나중에 넣은 것이 먼저 나옴top에서 push와 pop

배열로 만든 스택

2023년 2회 출제 isWhat[++point] = num으로 넣고 isWhat[point--]로 꺼내는 스택에 삽입·삭제를 섞어 가며 출력

int st[10], top = -1;                       // 비어 있으면 top = -1
void push(int x) { st[++top] = x; }         // top을 먼저 올리고 저장
int  pop(void)   { return st[top--]; }      // 현재 top 값을 꺼낸 뒤 내림

push(1); push(2);      // [1, 2]    top = 1
pop();                 // 2         top = 0
push(3);               // [1, 3]
pop(); pop();          // 3, 1      top = -1 (비어 있음)

스택 문제는 옆에 상자를 그려 두고 push는 위에 쌓고 pop은 맨 위에서 꺼내며 따라간다. ++top(전위)은 올린 뒤 쓰고, top--(후위)은 쓴 뒤 내린다.

앞에 삽입하는 연결 리스트 (malloc, free)

2025년 2회 출제 문자열의 글자를 하나씩 새 노드로 만들어 맨 앞에 연결한 뒤 처음부터 출력 → 역순으로 출력

struct node { char c; struct node *next; };
const char *s = "ABC";
struct node *h = NULL, *n;
while (*s) {                             // '\0'을 만날 때까지
    n = malloc(sizeof(struct node));     // 노드 하나 크기만큼 메모리 할당
    n->c = *s++;                         // 현재 글자를 넣고 s는 다음 글자로
    n->next = h;                         // 새 노드가 기존 머리를 가리킴
    h = n;                               // 새 노드가 새 머리
}                                        // 결과: C → B → A → NULL
while (h) {
    putchar(h->c);                       // CBA 출력
    struct node *t = h; h = h->next; free(t);   // 다 쓴 노드는 해제
}

맨 앞에 계속 붙이면 넣은 순서의 반대로 연결되어 스택처럼 동작한다. *s++는 현재 글자를 먼저 쓰고 포인터를 다음 글자로 옮긴다. 노드 연결을 여러 번 바꾸는 문제는 마지막으로 대입한 next를 기준으로 그림을 다시 그린다.

노드를 맨 앞으로 옮기기

2025년 1회 출제 연결 리스트에서 특정 값의 노드를 찾아 앞 노드와 끊고 맨 앞(head)으로 옮기기

// 1, 2, 3, 4를 차례로 맨 앞에 넣은 리스트: head → 4 → 3 → 2 → 1
N *prev = NULL, *cur = head;
while (cur && cur->v != 2) {     // 값이 2인 노드 찾기
    prev = cur;                   // 바로 앞 노드를 기억
    cur = cur->next;
}
if (cur && prev) {
    prev->next = cur->next;       // ① 3 → 1  (2를 목록에서 빼냄)
    cur->next = head;             // ② 2 → 4
    head = cur;                   // ③ 2가 새 head
}
// 결과: 2 → 4 → 3 → 1   출력: 2431

노드를 삭제할 때는 prev->next = cur->next로 건너뛰게 연결한 뒤 free(cur)를 한다. 연결을 바꾸는 코드는 한 줄씩 화살표를 고쳐 그리며 따라간다.

구조체와 트리 순회

2026년 2회 출제 구조체 포인터로 만든 이진 트리를 재귀로 후위 순회하면서, 전역 카운터 ++c로 몇 번째 방문 노드인지 찾는 문제

typedef struct Node {
    int v;
    struct Node *left, *right;   // 구조체 포인터: p->left 는 (*p).left 와 같음
} Node;

void post(Node *n) {             // 후위 순회
    if (!n) return;              // NULL이면 종료
    post(n->left);
    post(n->right);
    printf("%d ", n->v);         // 자식을 다 본 뒤 자신을 방문
}

//        1
//      /   \
//     2     3
//    / \
//   4   5
순회방문 순서위 트리 결과
전위 (Preorder)루트 → 왼쪽 → 오른쪽1 2 4 5 3
중위 (Inorder)왼쪽 → 루트 → 오른쪽4 2 5 1 3
후위 (Postorder)왼쪽 → 오른쪽 → 루트4 5 2 3 1

위 트리에서 후위 순회로 3번째 방문하는 노드는 2다. 코드에서 방문 위치(printf나 카운터)가 재귀 호출보다 앞에 있으면 전위, 사이에 있으면 중위, 뒤에 있으면 후위다.

재귀 함수 추적

2026년 2회 출제 c(n - 1) + c(n - 3)처럼 여러 번 자기 자신을 호출하고, 종료 조건에 음수가 들어가는 재귀

int f(int n) {
    if (n <= 1) return 1;          // 종료 조건
    return f(n - 1) + f(n - 2);
}
// f(0)=1, f(1)=1
// f(2)=f(1)+f(0)=2
// f(3)=f(2)+f(1)=3
// f(4)=f(3)+f(2)=5
// f(5)=f(4)+f(3)=8   → printf("%d", f(5)) 출력: 8

위에서부터 호출을 펼치면 길어지므로, 작은 n부터 값을 표로 채워 올라가면 빠르고 정확하다. 종료 조건이 return n이면 n이 0이나 음수일 때 그 값(0, −1 등)이 그대로 반환되는 점에 주의한다.

static 지역 변수

2024년 3회 출제 함수 안의 static 변수가 호출할 때마다 값을 유지하며 누적되는 문제 (main의 같은 이름 지역 변수와는 무관)

int counter(void) {
    static int n = 0;    // 프로그램 시작 때 한 번만 초기화, 함수가 끝나도 값 유지
    n += 1;
    return n;
}
int plain(void) {
    int n = 0;           // 호출할 때마다 새로 만들어지고 0으로 초기화
    n += 1;
    return n;
}
counter(); counter(); counter();   // 1, 2, 3
plain();   plain();   plain();     // 1, 1, 1
변수유효 범위수명
지역 변수선언한 블록 안블록이 끝나면 사라짐
static 지역 변수선언한 블록 안프로그램이 끝날 때까지 유지
전역 변수파일 전체프로그램이 끝날 때까지 유지

함수 안의 변수와 main의 변수는 이름이 같아도 서로 다른 변수다. static 변수를 초기화하는 줄은 첫 호출 이후에는 다시 실행되지 않는다.

    case 1:  r += 1;

    case 3:  r += 100;     // break가 없으니 계속 실행
             break;        // 여기서 switch 탈출
    default: r += 1000;    // 실행 안 됨
}
printf("%d", r);           // 110

switch는 일치하는 case부터 break를 만날 때까지 아래로 계속 실행한다(fall-through). 일치하는 case가 없으면 default부터 실행한다.

정렬 알고리즘

2023년 2회 출제 선택 정렬 코드에서 오름차순이 되도록 비교 연산자를 고르는 문제

int a[] = {5, 3, 1, 4, 2};   // n = 5

// 선택 정렬: i번 자리에 남은 것 중 가장 작은 값이 오도록 뒤쪽과 비교해 교환
for (int i = 0; i < n - 1; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] > a[j]) swap(a[i], a[j]);     // > 이면 오름차순 1 2 3 4 5, < 이면 내림차순 5 4 3 2 1

// 버블 정렬: 이웃한 두 값을 비교해 큰 값을 뒤로 보냄
for (int i = 0; i < n - 1; i++)
    for (int j = 0; j < n - 1 - i; j++)
        if (a[j] > a[j + 1]) swap(a[j], a[j + 1]);
// 첫 바퀴가 끝나면 가장 큰 값이 맨 뒤로: 3 1 4 2 5

// 삽입 정렬: 앞쪽은 정렬된 상태로 유지하고, 새 값을 알맞은 자리에 끼워 넣음
for (int i = 1; i < n; i++) {
    int key = a[i], j = i - 1;
    while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }   // 큰 값들을 한 칸씩 뒤로
    a[j + 1] = key;
}

선택 정렬남은 값 중 최솟값(최댓값)을 골라 앞자리부터 채움비교 횟수 n(n−1)/2, O(n²)

퀵 · 병합 정렬기준값(피벗)으로 나누기 · 반씩 나눠 정렬한 뒤 합치기평균 O(n log n)

    return y >= 0 && y < h && x >= 0 && x < w;
}
int g[3][3] = {{1, 0, 0},
               {0, 0, 1},
               {0, 0, 0}};
int c[3][3] = {0};
for (int y = 0; y < 3; y++)
    for (int x = 0; x < 3; x++) {
        if (g[y][x] == 0) continue;           // 지뢰가 아니면 건너뜀
        for (int i = y - 1; i <= y + 1; i++)  // 자기 자신을 포함한 3×3

// c = 1 2 1
//     1 2 1
//     0 1 1

int isPrime(int n) {                // 소수 판별
    if (n < 2) return 0;
    for (int i = 2; i * i <= n; i++)
        if (n % i == 0) return 0;
    return 1;
}

int gcd(int a, int b) {             // 최대공약수 (유클리드 호제법)
    while (b) { int t = a % b; a = b; b = t; }
    return a;
}
// gcd(48, 18) = 6

int fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }

서브넷 분할과 같은 네트워크 판별

2026년 2회 출제 /27 네트워크를 2개로 나눈 뒤의 프리픽스 길이, 주어진 네트워크에 속할 수 있는 호스트 IP 고르기

개념핵심
균등 분할한 네트워크를 2k개로 똑같이 나누면 프리픽스는 +k, 블록 크기는 ÷2k
예: /27(블록 32)을 2개로 나누면 → /28(블록 16): 10.0.0.0 ~ 10.0.0.15, 10.0.0.16 ~ 10.0.0.31
같은 네트워크 판별두 IP를 각각 서브넷 마스크와 AND한 네트워크 주소가 같으면 같은 네트워크
호스트에 줄 수 없는 주소블록의 첫 주소(네트워크 주소)와 마지막 주소(브로드캐스트 주소)

예: 192.168.10.0/26(블록 64)에 속하는 주소는 192.168.10.0 ~ 192.168.10.63이다. 이 중 호스트에 줄 수 있는 것은 .1 ~ .62이고, .63은 브로드캐스트 주소, .64는 다음 네트워크다.

예: 172.16.0.0/24를 4개로 나누면 22 = 4이므로 /26, 블록 64 → 세 번째 서브넷은 172.16.0.128 ~ 172.16.0.191

2026년 1회 출제 서브넷 마스크가 255.255.254.0(/23)처럼 옥텟 중간에서 끊길 때 네트워크 주소를 CIDR로 쓰기

마스크 값이 255도 0도 아닌 옥텟만 AND로 계산하면 된다. 예: 172.16.5.130 / 255.255.254.0 → 셋째 옥텟 5 AND 254 = 4 → 172.16.4.0/23. 10.1.37.5/22 → 셋째 옥텟 37 AND 252 = 36 → 10.1.36.0/22. /23은 셋째 옥텟이 2씩, /22는 4씩 묶인다(짝수, 4의 배수로 내림).

브로드캐스트를 받을 수 있는 호스트 = 같은 네트워크에 속한 호스트다 (2025년 1회 출제). 예: 10.0.5.9/22 → 네트워크 10.0.4.0 ~ 10.0.7.255이므로 10.0.4.1과 10.0.7.200은 받고, 10.0.8.1은 다른 네트워크라 받지 못한다.

전송 오류 제어 방식

방식설명

ARQ (자동 반복 요청)

수신 측이 오류 발생을 송신 측에 통보하면, 송신 측이 오류가 난 블록을 재전송한다.

종류설명
Stop-and-Wait ARQ정지-대기블록 1개를 보낸 뒤 수신 측의 응답을 기다림. 구현은 단순하지만 전송 효율이 떨어짐
Continuous ARQ연속Stop-and-Wait의 오버헤드를 줄이려고 데이터 블록을 연속으로 보냄
  • Go-Back-N: 오류가 난 블록부터 이후 블록을 모두 재전송
  • Selective Repeat: 오류가 난 블록만 골라 재전송

오류 검출·정정 방식

방식설명
Parity Check패리티 검사전송 비트에 패리티 비트 1비트를 추가해 오류 발생 유무만 판별
  • 홀수 패리티: 1의 개수가 홀수가 되도록 맞춤
  • 짝수 패리티: 1의 개수가 짝수가 되도록 맞춤
CRC순환 중복 검사다항식 코드로 오류 발생 유무를 판별. 집단 오류도 검출하고 검출률이 높아 HDLC 프레임의 FCS에 사용
Block Sum Check블록 합 검사블록의 맨 끝에 수평 방향 패리티 비트를 붙여 오류 발생 유무를 판별. 수평 패리티 검사, 세로 중복 검사(LRC)라고도 함
Hamming Code해밍 코드수신 측이 직접 오류를 검출하고 수정까지 하는 자기 정정 부호. 1비트 오류만 수정 가능

네트워크: 라우팅 프로토콜

데이터를 목적지까지 효율적으로 전달하기 위한 경로 결정 규칙

정적 라우팅
관리자가 경로를 수동으로 설정. 구성이 바뀌면 직접 갱신해야 함. 소규모 네트워크나 특정 경로를 강제할 때 적합하고 자원을 아낌
동적 라우팅
라우터끼리 경로 정보를 자동으로 교환해 최적 경로를 선택. 네트워크 변화에 유연하게 대처. 자치 시스템(AS) 범위에 따라 IGP와 EGP로 나뉨
프로토콜설명
IGPInterior Gateway Protocol같은 AS 내부에서 라우터 간 경로를 교환
RIPIGP · 거리 벡터홉 수를 기준으로 최단 경로를 찾음. 벨만-포드 알고리즘. 최대 15홉까지만 가능해 소규모 네트워크에 적합. 30초마다 라우팅 정보 갱신
OSPFIGP · 링크 상태링크 상태 정보로 최적 경로를 계산. 다익스트라 알고리즘. 홉 수 제한이 없어 중·대규모 네트워크에 적합. 영역(Area)으로 나눠 관리
EIGRPIGP · 고급 거리 벡터Cisco가 개발. 대역폭, 지연, 신뢰도 등 여러 요소를 고려해 경로를 설정. 대규모 네트워크에 적합
EGPExterior Gateway Protocol서로 다른 AS 사이에서 경로를 교환
BGPEGP · 경로 벡터인터넷의 AS 간 라우팅에 쓰는 대표 프로토콜. TCP(179번 포트) 위에서 동작해 신뢰성이 높음. 경로 길이, 라우팅 정책 등을 고려해 경로를 선택

RIP 경로 선택 RIP는 링크 비용(대역폭, 지연)을 보지 않고 홉 수(거치는 라우터 수)만으로 최단 경로를 고른다. 비용 합이 더 커도 홉이 적은 경로를 택한다 (2024년 2회 출제). 비용 합으로 고르는 것은 OSPF다.

짝 외우기 RIP = 거리 벡터 = 벨만-포드 = 홉 수 · OSPF = 링크 상태 = 다익스트라
